Writing plugins

Write your own tools for FlowCHAOS in Python: what a plugin is, how it is found, loaded and shared.

What a plugin can do

A plugin is Python code that FlowCHAOS loads at start-up (or when you enable it). It can:

  • add commands to the Plugins menu;
  • read the whole project: nodes, links, their values, every imported field, settings and results;
  • change the network, as one step the user can undo;
  • run analyses, use the design tools and read their results;
  • open its own windows and dialogs with Qt (PySide6);
  • add tools to the Processing Toolbox, with parameters, help, a log and a result table;
  • add rate sources to the BOQ Workbench (a rate database, a supplier's price list);
  • read and write files: reports, exports, imports from your own formats.

Plugins are grouped by what they add: GIS (data sources, formats, map tools), CAD (drawing and editing tools), Optimisation (design and operation optimisation), Reporting (reports and exports), Cost estimation (rates and estimates) and Engineering tools (any other calculation).

A plugin in two files

A plugin is a folder with a manifest and an entry point:

pipe_report/
    plugin.json
    __init__.py

plugin.json describes it:

{
  "id": "pipe-report",
  "name": "Pipe Report",
  "description": "Length of pipe by diameter, as a table you can copy.",
  "version": "1.0.0",
  "category": "Reporting",
  "min_flowchaos": "0.15.0",
  "startup": true
}
Key Meaning
id unique, lower case letters, digits, - and _, starting with a letter or digit
name shown in the Plugins panel and menus
description one sentence shown in the Plugins panel
version your version number
category GIS, CAD, Optimisation, Reporting, Cost estimation, Engineering tools or Other
min_flowchaos the oldest FlowCHAOS version it works with (an older one refuses to load it)
startup true to load it when FlowCHAOS starts (the user can switch it off)

__init__.py defines register(host), called once when the plugin loads:

def register(host):
    def run():
        project = host.document.project
        ...

    host.add_plugin_action("Pipe Report", run, "Length of pipe by diameter")

An optional unregister(host) is called when the plugin is switched off. Everything added through the host (commands, toolbox tools, rate sources) is removed automatically.

A Processing Toolbox tool

A tool declares its parameters; the toolbox builds its window, runs it as one undoable step when it changes the network, shows its message and table, and selects what it returns on the map:

from flowchaos.core.processing import Algorithm, Outcome, Param


def long_pipes(project, values, context):
    limit = values["limit"]
    rows, select = [], set()
    for link in project.links:
        if link.link_type == "PIPE" and project.link_length_m(link) > limit:
            rows.append([link.name, round(project.link_length_m(link), 1)])
            select.add(("link", link.id))
    return Outcome(f"{len(rows)} pipes longer than {limit:g} m.", ["Pipe", "Length (m)"], rows, select=select)


def register(host):
    host.add_toolbox_algorithm(Algorithm(
        "my_long_pipes", "Find long pipes", "My tools", "tb-plugin",
        "Selects the pipes longer than the limit.",
        (Param("limit", "Longer than", "number", 500.0, suffix=" m"),),
        long_pipes, needs="links"))

changes=True makes the run an undoable edit of the project; parameter kinds are number, integer, choice (with options), bool, text and file. A new group gets its own heading.

A rate source for bills of quantities

def register(host):
    def supplier_prices(boq):
        return {"Supply, lay, joint and test 110 mm OD uPVC PN10 pipe": 18.40}  # description -> rate

    host.add_rate_source("Supplier price list", supplier_prices)

The BOQ Workbench lists it under Rates; matching items without a rate are priced from it.

Managing plugins

Plugins > Manage Plugins lists the installed plugins with their version, author and description. Its buttons install a plugin from a ZIP file, open the Plugin Builder (a form that writes a new plugin with the parts you choose, ready to edit), reload the plugins after you change one, open the plugin folder and uninstall the selected plugin. A sample, the Design Check Report, is in docs/plugins and the tutorial Build a plugin walks through writing one.

Where plugins live

Location For
%USERPROFILE%\.flowchaos\plugins\<id>\ your own plugins (copy the folder here)
flowchaos/plugins_builtin/<id>/ plugins shipped with FlowCHAOS

The Plugins panel lists every plugin, switches them on and off, installs a plugin from a .zip archive (one folder with one plugin.json) and removes user plugins.

Developing a plugin

  1. Watch the log (%LOCALAPPDATA%\FlowCHAOS\FlowCHAOS\logs\flowchaos.log): a plugin's Python errors are written there.
  2. Create the folder in %USERPROFILE%\.flowchaos\plugins\ and restart FlowCHAOS. After a change, switch the plugin off and on again in the Plugins panel to load the new code.
  3. Errors while loading are shown in the Plugins panel and written to the log; FlowCHAOS keeps running.
  4. Keep calculations in plain functions that take a project and return values: they are easy to test with pytest without opening a window.

Rules of thumb

  • Change the project through host.document.apply, never directly: the change is undoable, saved and every view refreshes. See the plugin API.
  • Long work on a worker thread: use flowchaos.core.workers.submit and update the window when it finishes, so the map stays responsive.
  • Plain, clear text in your commands and messages.
  • Store your plugin's settings in project.settings["plugin:<id>"] when they belong to the project, or in QSettings when they are personal.

Sharing

Zip the plugin folder (the zip contains pipe_report/plugin.json and pipe_report/__init__.py) and share it. Others install it from the Plugins panel. Plugins for everyone can be proposed for plugins_builtin through a pull request.

Reference data

Design tables are JSON files under flowchaos/resources/data/: pipe series for automatic sizing (design/pipe_series.json), regional settings and rates for quantities, irrigation tables. Each file starts with a _help entry explaining its fields. To change the data of an installed copy without rebuilding, put a file with the same relative path in %APPDATA%\FlowCHAOS\data; it is used instead of the shipped one.
