Tutorial: build a plugin

Tutorial: build a FlowCHAOS plugin step by step, from an empty folder to a ZIP your colleagues install.

This tutorial builds Design Check Report, a plugin that lists, after a run, every pressure, velocity and head loss outside your design limits, in a window of its own and as a tool in the Processing Toolbox. The finished plugin comes with FlowCHAOS as an example (FlowCHAOS-Design-Check-1.0.0.zip); building it yourself shows every part a plugin can have. You need FlowCHAOS and a text editor; Python knowledge helps but each step shows the full code.

Step 1: let the Plugin Builder make the folder

Plugins > Plugin Builder... writes a complete, working starting folder:

  1. Name: Design Check Report.
  2. Description: Pressures, velocities and head losses outside the design limits, after a run.
  3. Category: Engineering tools.
  4. Leave the three parts ticked (a command, a tool window, a toolbox tool), keep Install it in FlowCHAOS and switch it on now ticked and press Build Plugin.

The builder writes the folder (by default in Documents\FlowCHAOS plugins), installs it and switches it on: the Plugins menu now has its commands and the Processing Toolbox its tool. The folder opens in Explorer:

design_check_report/
    plugin.json          the manifest
    __init__.py          register(host): what the plugin adds to FlowCHAOS
    tools.py             the plugin's own work, without windows
    README.md            what it does and how to install it
    tests/test_tools.py  a first test

Step 2: the manifest

plugin.json tells FlowCHAOS what the plugin is:

{
  "id": "design-check-report",
  "name": "Design Check Report",
  "description": "Pressures, velocities and head losses outside the design limits, after a run.",
  "version": "0.1.0",
  "category": "Engineering tools",
  "min_flowchaos": "1.0.0",
  "startup": true
}

The id must be unique; min_flowchaos is the oldest FlowCHAOS your plugin works with (an older one refuses to load it, with a clear message); startup loads it each time FlowCHAOS starts. The keys are explained in Plugins.

Step 3: keep the work apart from the windows

Put the calculation in a module of its own, checks.py, with plain functions on the project. They need no window, so they are easy to test and to reuse in a menu command, a window and a toolbox tool alike:

from dataclasses import dataclass

DEFAULTS = {"min_pressure_m": 10.0, "max_pressure_m": 60.0, "min_velocity_mps": 0.3,
            "max_velocity_mps": 2.0, "max_headloss_m_per_km": 10.0}


@dataclass
class Finding:
    kind: str          # "node" or "link"
    element_id: str
    name: str
    check: str
    value: float
    limit: float
    severity: str      # "High", "Medium" or "Low"


def check_design(project, limits=None):
    limits = {**DEFAULTS, **(limits or {})}
    results = project.results or {}
    nodes = {row["name"]: row for row in results.get("nodes", [])}
    found = []
    for node in project.nodes:
        row = nodes.get(node.name)
        if node.node_type != "JUNCTION" or row is None:
            continue
        pressure = float(row["pressure_m"])
        if pressure < limits["min_pressure_m"]:
            found.append(Finding("node", node.id, node.name, "Pressure below the minimum (m)",
                                 pressure, limits["min_pressure_m"], "Medium"))
    return found

What the project holds is in The project model: project.nodes and project.links with their values, project.results after a run (one row per node and link, with pressure_m, head_m, flow_lps, velocity_mps, headloss_m), and project.link_length_m(link). The full checks.py of the example also checks velocities, head loss per kilometre and dead ends.

Step 4: register what the plugin adds

__init__.py defines register(host). FlowCHAOS calls it when the plugin is switched on and gives it the host, the main window (Plugin API):

from . import checks


def register(host):
    host.add_tool_window("design-check-report", "Design Check Report", lambda: _window(host),
                         "Pressures, velocities and head losses outside the design limits")

add_tool_window puts a command in the Plugins menu that opens your window beside the map, one at a time. add_plugin_action(text, callback, tooltip) adds a plain command instead.

Step 5: a window of your own

A window is ordinary Qt (PySide6). Build it in a function that returns it:

def _window(host):
    from PySide6.QtWidgets import QLabel, QPushButton, QTableWidget, QTableWidgetItem, QVBoxLayout, QWidget

    window = QWidget()
    window.setWindowTitle("Design Check Report")
    layout = QVBoxLayout(window)
    summary = QLabel("Run a steady-state analysis, then Check.")
    table = QTableWidget(0, 4)
    table.setHorizontalHeaderLabels(["Severity", "Check", "Element", "Value"])
    check = QPushButton("Check")
    layout.addWidget(summary)
    layout.addWidget(table, 1)
    layout.addWidget(check)

    def run_check():
        found = checks.check_design(host.document.project)
        table.setRowCount(len(found))
        for r, f in enumerate(found):
            for c, value in enumerate((f.severity, f.check, f.name, round(f.value, 2))):
                table.setItem(r, c, QTableWidgetItem(str(value)))
        summary.setText(f"{len(found)} finding(s).")
        host.canvas.set_selection({(f.kind, f.element_id) for f in found})  # shown on the map

    check.clicked.connect(run_check)
    return window

host.canvas.set_selection({("node", id), ("link", id)}) selects elements on the map; the user sees them highlighted and can zoom to them with Ctrl+J.

Step 6: a tool in the Processing Toolbox

A toolbox tool declares its parameters; FlowCHAOS builds the form, the help, the log, the result table and the map selection:

def _toolbox_run(project, values, context):
    from flowchaos.core.processing import Outcome

    found = checks.check_design(project, values)
    return Outcome(f"{len(found)} finding(s).", ["Severity", "Check", "Element"],
                   [[f.severity, f.check, f.name] for f in found],
                   select={(f.kind, f.element_id) for f in found})


def register(host):
    from flowchaos.core.processing import Algorithm, Param

    host.add_toolbox_algorithm(Algorithm(
        "design_check_report", "Design check report", "Checks", "tb-check",
        "Every value of the last run outside the limits.",
        (Param("min_pressure_m", "Minimum pressure", "number", 10.0, suffix=" m"),),
        _toolbox_run, needs="results"))

needs keeps the tool greyed until it makes sense: network, links, selection, results or none. A tool that changes the network sets changes=True: the toolbox then runs it as one step of Undo, and new elements join the network layer being edited.

Step 7: changing the network

Every change goes through the document, as one step the user can undo:

def set_material(project):
    for link in project.links:
        if link.link_type == "PIPE" and link.diameter_mm <= 110:
            link.attributes["material"] = "HDPE"

host.network_edit("Set materials of small pipes", set_material)

host.network_edit(label, edit) makes the change in the network layer being edited (and asks which layer when several exist); host.document.apply(label, edit) changes the project as a whole (settings, results). Never keep project.nodes or a node between two edits: each edit makes a new project, so read host.document.project again each time.

Step 8: long work in the background

A calculation that takes more than a moment must not freeze the window. Run it on a worker and hand the result back with a Qt signal:

from PySide6.QtCore import QObject, Signal
from flowchaos.core import workers


class Done(QObject):
    finished = Signal(object)


done = Done()
done.finished.connect(show_results)        # runs on the window's thread
project = host.document.project            # read here, then work on it there
workers.submit(lambda: done.finished.emit(checks.check_design(project)), pool_name="compute")

Never touch windows from the worker: compute there, show the result in the connected function.

Step 9: try it while you write it

  1. Edit the files of the installed copy (Plugins > Manage Plugins > Open Plugin Folder), or build again with the Plugin Builder.
  2. Press Reload in Plugins > Manage Plugins: the plugin is switched off and on again, reading its files anew. No restart is needed.
  3. An error while loading is shown in the Plugin Manager (point at the plugin's name) and written to the log (Help > Open Crash Log Folder, flowchaos.log).

Test the plain functions with pytest, without starting FlowCHAOS:

from flowchaos.core.sample_library import town_water_supply
from flowchaos.core.solver_backend import run_with_best_backend
from flowchaos.ui.main_window import prepare_results

import checks


def test_finds_high_pressures():
    project = town_water_supply()
    project.results, _message = prepare_results(run_with_best_backend(project))
    assert any(f.check.startswith("Pressure above") for f in checks.check_design(project))

Step 10: share it

Zip the folder (the folder itself, with plugin.json inside it) and send the ZIP. Your colleagues install it with Plugins > Manage Plugins > Install from ZIP and tick it. Raise version in plugin.json for each new release; installing a newer ZIP replaces the older one.

Good practice

  • Name things as the engineer sees them: "Design check report", not "dcr_tool".
  • Keep the calculation in plain functions and test them; keep windows thin.
  • Every change through network_edit or document.apply, never by changing host.document.project directly, so Undo and the map stay right.
  • Work longer than half a second goes to a worker (Step 8).
  • unregister(host) stops anything the plugin started itself: timers, threads, open files. What was added through the host is removed by FlowCHAOS.
  • A plugin runs with the user's permissions: write only to files the user chooses.

More examples are in Plugin examples; every call is in Plugin API.
